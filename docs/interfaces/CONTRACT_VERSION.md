| 项 | 值 |

> **为什么是 `PROPOSED_V1` 而不是 `FROZEN_V1`**

> 本文件不会声称"所有开发成员均已确认"。

## 1. 四种"版本"必须分开

开发中经常把不同的"版本"混为一谈，导致排查困难。本项目明确区分：

| 版本类型 | 含义 | 本仓库中的体现 |
| --- | --- | --- |
| **Schema 版本** | 数据契约的版本，决定字段含义与校验规则 | `schema_version` 字段，当前仅 `1.0.0-proposed` |
| **模块实现版本** | 某个模块代码的版本，决定其行为与算法 | 输出中的 `producer.module_version` |
| **Git 源代码提交** | 仓库在某一时刻的完整快照 | 提交 SHA，例如 F0 基线 `c2d600d` |
| **系统运行版本** | 一次实际运行所组合的版本集合 | 由 `run_id` 关联，需同时记录前三者 |

**规则**：任何一次接口变更都必须同时记录"Schema 版本 + 涉及的模块实现版本 + Git 提交"。
只写其中一个不足以判断兼容性。

## 2. v1.0 字段总览

三个输出接口共享一组**公共元数据**，并使用**相同含义**（值域因接口而异）：

| 字段 | 类型 | 必填 | 可为 null | 是否可自报 | 是否参与安全决策 |
| --- | --- | --- | --- | --- | --- |
| `schema_version` | string | 是 | 否 | 是 | 否（仅决定校验规则） |
| `run_id` | string | 是 | 否 | 是 | 否（仅用于关联） |
| `request_id` | string | 是 | 否 | 是 | **否**（业务串联，非身份） |
| `event_id` | string | 是 | 否 | 是 | 否（审计追溯） |
| `producer` | object | 是 | 否 | **是**（**非认证凭据**） | 否 |
| `observed_at` | string(date-time) | 是 | 否 | 是 | 否 |
| `status` | enum | 是 | 否 | 是 | 供适配层参考，**不构成最终授权** |
| `reason` | string | 是 | 否 | 是 | 否 |
| `evidence_refs` | array | 是（≥1 条） | 否 | 是 | 用于判断证据强度 |
| `extensions` | object | 否 | 否 | 是 | 否（预留扩展位） |

各接口的 `status` 取值域：

| 接口 | status 取值 |
| --- | --- |
| `CommRiskEvidence` | `NORMAL` / `SUSPICIOUS` / `UNKNOWN` / `ERROR` |
| `IdentityTrustAssessment` | `AUTHORIZED` / `DENIED` / `UNKNOWN` / `ERROR` |
| `TaskRiskDecision` | `ALLOW_RECOMMENDED` / `BLOCK_RECOMMENDED` / `UNKNOWN` / `ERROR` |

接口特有字段与完整约束见对应 Schema 文件（`schemas/` 目录）。

## 3. 字段规则约定

| 规则 | 约定 |
| --- | --- |
| **时间格式** | RFC 3339 日期时间，**必须带时区**（`Z` 或 `±hh:mm`）。`2026-10-10 12:00:05`（空格分隔）与 `2026-10-10T12:00:05`（缺时区）均不合法。 |
| **必填字段** | 不得隐式省略。缺失即校验失败，由适配层拒绝本次候选操作。 |
| **空值** | 必填字段不接受 `null`。可选字段缺失表示"未知"，**不得用零值或占位常量填充**。 |
| **数值边界** | 所有数值字段声明上下界。超出上界（含 `Infinity`）校验失败。 |
| **非有限数值** | `NaN` / `Infinity` / `-Infinity` **不是合法 JSON**，必须在解析阶段拒绝，不得进入 Schema 校验。 |
| **字符串长度** | 所有字符串声明长度上界，避免超长输入。 |
| **未知字段** | 首版采用**严格校验**（`additionalProperties: false`）。未来扩展只能放入显式声明的 `extensions` 对象。 |
| **版本不兼容** | `schema_version` 不在允许枚举内即拒绝，**不得静默猜测字段含义**。 |
| **`UNKNOWN` 语义** | 表示"证据不足"，**不得被解释为正常或允许**。 |
| **`ERROR` 语义** | 表示模块自身执行失败，**不得被解释为允许**。 |
| **`producer` 语义** | 自报信息，**不是安全认证凭据**，不得作为身份判断依据。 |
| **`evidence_refs.kind`** | 必须标注证据可信级别，区分 `MOCK` / `RUNTIME_LOG` / `PERMISSION_FILE_ANALYSIS` / `CONTROLLED_SECURITY_EXPERIMENT` / `UNIT_TEST` / `UNKNOWN`。 |

## 4. 变更规则

### 4.1 兼容扩展（允许，仍须评审）

- 在 `extensions` 对象内增加字段（消费方必须容忍未知键）；
- 增加**新的可选**字段，且不改变既有字段语义；
- 增加文档说明、示例与测试（不改变校验行为）。

### 4.2 破坏性变更（必须升级版本并走完整评审）

- 删除或重命名任何字段；
- 把可选字段改为必填；
- 收窄枚举取值域（例如删除某个已有枚举值）；
- 修改字段类型、数值边界或单位语义；
- 改变 `status` / `denial_layer` 等安全语义字段的含义；
- 放宽 `additionalProperties`（会掩盖拼写错误，属破坏性）。

### 4.3 枚举扩展的特殊约定

新增枚举值**视为破坏性变更**：消费方若用穷举分支处理枚举，新增值会落入未定义分支。
因此新增枚举值必须：

1. 升级契约版本；
2. 明确消费方对未知枚举值的**保守处置**（拒绝，而非放行）；
3. 同步更新样例与测试。

### 4.4 未知版本的处理

收到不认识的 `schema_version` 时：

- **拒绝继续处理**，形成可解析的本地拒绝记录；
- 不得尝试按已知版本解释字段；
- 不得忽略版本字段继续执行。

### 4.5 变更流程

| 步骤 | 要求 |
| --- | --- |
| 1 | 提交变更说明：改什么、为什么、影响哪些接口 |
| 2 | 更新 Schema 与样例（正常、异常、UNKNOWN/ERROR、非法各至少一份） |
| 3 | 运行契约校验与单元测试，全部通过 |
| 4 | 相关开发者确认（数据契约变更需共同确认） |
| 5 | 更新本文件与 `README.md`，记录评审结论 |
| 6 | 记录新的契约版本与生效提交 SHA |

**在步骤 4 完成前，契约状态保持 `PROPOSED_V1`。**

## 5. 强制安全边界（八条）

以下规则是接口设计的一部分，不是建议。任何模块实现都不得违反。

### 规则一：身份与来源
模块输出中的 `producer`、`node_name`、`enclave` 等字段**不是安全认证凭据**。
JSON 中写有 `/planner`、`/gateway` 或任何角色名，**不等于**该主体已通过 DDS-Security 认证。

### 规则二：授权边界
只有**原有的 Gateway 与 DDS-Security** 在各自层面具有权威判断能力。
研究模块的输出不构成授权。

### 规则三：风险建议
上游风险模块**不能**通过输出 `ALLOW_RECOMMENDED` 绕过 Gateway。
即使全部 Mock 输出允许，仍必须经过 `/rg/guarded_navigate` 由 Gateway 判定。

### 规则四：故障状态
上游结果为 `UNKNOWN`、`ERROR`、超时或结构无效时，**默认不得推动候选 Action 执行**。
适配层应形成可解析的本地拒绝记录，且**不得把适配层的阻断伪装成**访问控制拒绝或 Gateway 策略阻断。

### 规则五：版本一致性
输入输出 Schema 不兼容时**拒绝继续处理**，不允许静默猜测字段含义。

### 规则六：证据可信性
必须区分证据来源等级：`MOCK`（模拟，**不构成任何安全保证**）、`PERMISSION_FILE_ANALYSIS`（配置推导）、
`RUNTIME_LOG`（运行日志观察）、`CONTROLLED_SECURITY_EXPERIMENT`（受控安全实验）、`UNIT_TEST`（单元断言）。
模拟实验的结果**不得**被包装成"已完成真实安全验证"。

### 规则七：M3 扩展
F0 不依赖任务动态状态机。`task_phase`、`policy_epoch`、`policy_digest` 在 F0 下均为**可选字段**，
缺失不得导致正常输入被拒绝；同时**不得**用零值、随机值或 Mock 常量冒充真实策略版本。
只有在可信来源明确后才可填写。

### 规则八：执行链路
最终业务操作必须经过 `/rg/guarded_navigate`。
`candidate_action.action_resource` 在 Schema 层被固定为该值（`const`），
**上游模块无法通过配置或参数把候选操作指向执行端 `/rg/nav_execute`**。

## 6. 输入输出协议（进程级）

适用于后续 Mock 与真实模块的统一调用方式：

| 通道 | 约定 |
| --- | --- |
| **stdin** | 传入**一个** JSON 对象（`ModuleInputEnvelope`） |
| **stdout** | 输出**一个** JSON 对象（对应接口的输出），**不得混入调试日志** |
| **stderr** | 诊断信息（日志、堆栈），不得作为结果解析 |
| **退出码** | `0` 表示进程正常执行（**不代表业务结论为允许**）；非 `0` 表示进程异常 |
| **超时** | 由调用方统一管理；超时结果视为不可用 |
| **调用方式** | 使用参数数组执行，**不得用 shell 字符串拼接**；可执行路径来自本地受信任开发配置 |

**重要**：JSON 结构校验成功只意味着**格式有效**，不能证明 JSON 来源可信，
也不能证明其中的任何安全结论成立。

## 7. 关联与一致性约定

| 场景 | 约定 |
| --- | --- |
| `request_id` 贯穿 | 输入信封与三个模块输出必须使用**相同** `request_id` |
| 不一致处置 | 适配层发现不一致时**拒绝本次候选操作**，不得串单 |
| `run_id` | 同一次运行内保持一致，用于跨模块关联 |
| `task_id` / 候选动作不一致 | 视为输入与输出不匹配，拒绝 |
| 超时输出 | **不可使用** |
| 过期观察 | 由模块按契约自行判定并如实标注，不得沉默使用 |
| 一次运行多个事件 | 通过不同 `event_id` 区分，同一 `run_id` 下可多条 |
| 重复输出 | 以 `event_id` 去重；重复且内容不同的输出应被拒绝并记录 |

**注意**：跨文件、跨模块的一致性**无法由单份 JSON Schema 证明**，
必须由适配层语义检查与独立语义测试覆盖（见 `tests/unit/test_team_contracts.py`
中的 `test_mismatched_request_id_is_detectable_by_semantic_rule`）。

以下问题需要在团队评审中确认。**在此之前契约保持 `PROPOSED_V1`。**

| 编号 | 待确认事项 | 当前倾向 | 影响 |
| --- | --- | --- | --- |
| Q1 | 三个接口的字段是否足够覆盖各自研究需求 | 现状为基础集合 | 不足则需在冻结前补齐 |
| Q2 | 业务枚举是否合理（异常类别、风险等级取值） | 现状为常用集合 | 影响算法输出表达力 |

| Q4 | `UNKNOWN` 的业务处置是否统一为"不得推动执行" | 是 | 影响误报/漏报权衡 |
