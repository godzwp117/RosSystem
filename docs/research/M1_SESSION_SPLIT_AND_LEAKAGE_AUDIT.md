# M1 会话独立性与标签泄漏审计

> run_id：`m1retrain-20261020T023546Z`
> 审计脚本：`scripts/m1_leakage_audit.py`
> 证据：`artifacts/research/m1-trusted-retraining/m1retrain-20261020T023546Z/leakage_audit.json`

## 1. 划分单位

**会话**（`session_id`），不是窗口。所有留一评估都留出**整个会话**，
同会话的窗口绝不跨训练/测试。规范见 `M1_TRUSTED_DATA_COLLECTION_SPEC.md` §1–2、§15。

## 2. 禁止特征检查（结果：通过）

代码里 `FORBIDDEN_FEATURES` 列出并断言不得出现的字段：

```
duration_ms, window_start, window_end, segment_index,
session_id, scenario, resource, topic, label, label_basis
```

实测 `forbidden_features_present = []`，即**没有任何被禁字段进入特征**。
特别地：第三轮导致 0.9919 的 `duration_ms` **不在特征中**，
而且窗口固定 30 秒，该字段本身也已无信息量。

## 3. 允许特征与单特征判别力

| 特征 | AUC | 判读 |
| --- | --- | --- |
| `message_count` | **1.000** | 单独就能完美分开 |
| `frequency_hz` | **1.000** | 同上（与上者几乎等价） |
| `gap_cv` | 0.667 | 中等 |
| 其余 | — | 受样本量限制不稳定 |

### 这个 AUC=1.0 意味着什么（必须说清）

它**不是**"模型很强"，而是**任务太窄**：本轮唯一的可用异常是
2000 Hz 洪泛，而正常最高是 500 Hz，两者在消息计数上差一个数量级。

也就是说，在这个数据集上"检测"退化成了**"速率是否超过某个阈值"**。
这正是规范 §10 警告的情况：如果模型只学到一条频率阈值，
它在真实高负载业务（例如合法的 2000 Hz 视频流）上会大量误报。

**因此本轮不宣称已获得有意义的检测能力。** 该 AUC 是数据集局限的体现，
不是模型有效性的证据。

## 4. 重复窗口

`distinct = 14, max_repeat = 1` —— 没有完全相同的特征向量，
不存在"同一窗口被计数多次"的问题。

## 5. 特征消融

因可用窗口仅 14 个、异常窗口仅 2 个，消融实验**没有统计意义**，
本轮**不做**消融结论（避免用 2 个样本编造"去掉 X 后指标下降"的叙事）。

## 6. 时间邻近泄漏

窗口不重叠（规范 §5），同一会话相邻窗口不跨划分；
但同会话窗口之间仍存在**时间自相关**，这是窗口模型的固有局限，
已在规范 §1 明确记录，不声称已消除。

## 7. 数据生成器差异

所有会话由**同一个采集器、同一份代码、同一个容器**产生，
因此"生成器差异"在本轮不构成泄漏渠道；
但也意味着本轮无法检验跨生成器的稳健性。
