### ⚠️ 必须区分的四类"身份"

| 类别 | 说明 | 能否作为认证结论 |
| --- | --- | --- |
| **配置层面的权限判断** | 从 Permissions 文件读出的理论授权 | 是**配置事实**，不是运行时结果 |
| **真实 DDS 访问拒绝** | 安全插件实际拒绝并给出原生报错 | **可以**作为拒绝证据 |
| **应用层业务身份** | 业务字段里的角色/名称 | **不能**当作 DDS 身份 |
| **ROS 2 `request_id`** | 业务请求标识 | **不是** DDS 身份 |
| **Mock 自报身份** | `producer.source = MOCK` 的输出 | **不是**认证证明 |

- 把普通字符串 `AUTHORIZED` 解释为 "DDS 完成了身份认证"；
- 把 ROSPaCe 的异常分类标签**伪装成** DDS 身份认证结论。

`ROSPaCe reduced` 是**通信流量/系统指标**数据集，
**不承担 DDS 认证真值**。它的标签是攻击类型，不是身份授权结果。
**不得**把它的标签挪用作你的身份标签。

## 7. 模块输入与输出契约

**输入**：stdin 一个 `ModuleInputEnvelope`（JSON）
**输出**：stdout 一个 `IdentityTrustAssessment`（JSON）
**诊断日志**：**stderr**（stdout 只能有一个 JSON 对象）

**状态语义**：与通信模块一致 ——
`AUTHORIZED` 允许推进；`DENIED` / `UNKNOWN` / `ERROR` 一律**阻断**。

**重要约束**：

- `producer.source` 只能是 `MOCK` / `EXTERNAL` / `UNKNOWN`。
- `evidence_refs[].kind` 只能是 `MOCK` / `RUNTIME_LOG` / `PERMISSION_FILE_ANALYSIS` /
  `CONTROLLED_SECURITY_EXPERIMENT` / `UNIT_TEST` / `UNKNOWN`。
  你的 DDS 拒绝证据应当用 `CONTROLLED_SECURITY_EXPERIMENT` 或 `RUNTIME_LOG`。
- **不要修改 Schema 来迁就你的输出。**

## 9. 实验与评价指标

- **正向对照成功率**：授权身份访问目标资源应成功
- **反向拒绝率**：越权身份访问应被拒，且**有原生拒绝证据**
- **证据可归因性**：拒绝必须能指向 DDS 安全插件报错，**不能只是客户端超时**
- **失败关闭率**：证据不足 / 配置缺失 / 解析失败时必须 `UNKNOWN` 并阻断
- **误报率**：授权身份被错误拒绝的比例

**报告要求**：每次拒绝都要给出**文件证据**（日志行、审计记录），
不接受"客户端超时所以推断是权限拒绝"。

## 11. 必须完成的测试

**单元测试**

- Enclave / Permissions 解析正确（含畸形配置）
- 配置缺失 / 解析失败 → 必须失败关闭为 `UNKNOWN`，**不得默认 `AUTHORIZED`**
- 证据不足（只有配置判断、无原生拒绝证据）→ 必须降级，不得输出确定结论
- 业务 `request_id` 不得被当作 DDS 身份

**集成测试**

- **正向对照**：授权身份访问 → 成功 → 模块 `AUTHORIZED`
- **反向拒绝**：越权身份访问 → 原生拒绝 → 模块 `DENIED` → 适配层 `ADAPTER_BLOCK`
- 正常路径 → `AUTHORIZED` → `READY_FOR_GATEWAY_SUBMISSION`
- 拒绝证据必须**可归因到 DDS 安全插件**，不能只是超时
