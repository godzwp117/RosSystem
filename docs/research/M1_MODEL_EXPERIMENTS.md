## 1. 设计动机

`M1_DATA_AUDIT.md` 已证明：按文件划分等价于按攻击类别划分，因此旧指标
（F1 0.1312 / 0.0891）测的是跨类别迁移，不是检测能力。

本次改用**窗口级特征**，因为它同时满足两个必要条件：

1. **运行时真实可观测**：窗口内消息数、频率、到达间隔统计、窗口时长，
   都能从 ROS 2 订阅侧测出来（见 `M1_ROS2_RUNTIME_COLLECTOR.md`）；
2. **可按会话分组评估**：窗口数据带 `segment_index`，据此做 GroupKFold，
   训练/验证不共享采集会话。

## 2. 数据与方法

| 项 | 值 |
| --- | --- |
| 输入 | `data/ROSPaCe_reduced/windows_0.jsonl`（22,591 个窗口） |
| 标签 | `observe` 11347 / `nmap discovery` 10845 / `ros2 reconnaissance` 399 |
| 二分类定义 | 攻击 = 非 `observe` |
| 特征（6 维） | `request_count`、`frequency_hz`、`gap_median_ms`、`gap_p95_ms`、`gap_max_ms`、`duration_ms` |
| 划分 | `GroupKFold(n_splits=5)` by `segment_index` |
| 插补 | **训练折**中位数（不得用全量，否则泄漏） |
| 阈值 | **只用训练折**选（候选 0.05–0.9），验证折不参与 |
| 基线 | 恒预测攻击 / 恒预测正常 / 频率 99 分位规则 |

## 3. 结果（会话分组交叉验证）

| 候选 | 平均 F1 | 最差折 F1 | 最好折 F1 |
| --- | --- | --- | --- |
| `logistic` | **0.9946**（带资源）/ **0.9961**（不带资源） | 0.9729 / **0.9803** | 1.0 |
| `extra_trees` | 0.9840 / 0.9903 | 0.9319 / 0.9514 | 1.0 |
| `random_forest` | 0.8916 / 0.8959 | 0.4999 / 0.5193 | 1.0 |
| `hist_gb` | 0.7977 / 0.7977 | **0.0055** | 1.0 |
| `rule_frequency_99pct` | **0.3290** | **0.0000** | 0.8+ |
| 恒预测攻击（基线） | **0.6411** | — | — |

### 3.1 三个必须一起看的事实

1. **有候选显著超过平凡基线**：`logistic` 平均 0.9946、最差折 0.9729，
   而恒预测攻击只有 0.6411。这不是"靠多数类蒙对"，因为最差折仍然远高于基线。
2. **简单规则不够**：只用"频率 > 训练折正常 99 分位"的规则平均 F1 只有 0.3290，
   最差折为 0。**说明学习到的模型确实带来了规则给不了的信息**，
   这一点防止了"其实一条阈值就够、模型是多余的"这种质疑。
3. **`hist_gb` 是最差折杀手**：平均 0.7977 但最差折 0.0055 ——
   某一场采集完全失效。这类模型在演示里不可用，因此**不选用它**，
   尽管它的平均值看起来"也能过线"。

### 3.2 消融：信号来自行为，不是资源名

担心"模型只是记住了资源名（如 `未标注话题` 恒对应扫描）"，因此做了
**去掉 resource one-hot** 的消融：

| 配置 | logistic 平均 F1 | 最差折 |
| --- | --- | --- |
| 6 数值特征 + 资源 one-hot | 0.9946 | 0.9729 |
| **仅 6 数值特征（无资源）** | **0.9961** | **0.9803** |

**去掉资源名后指标没有下降，反而略升。** 说明判别信号来自频率/间隔这类
**行为特征**，而不是资源命名。这条消融是本轮最重要的可信度证据之一。

## 4. 部署模型

`modules/member1_comm/model/comm_risk_window_model.json`：

| 项 | 值 |
| --- | --- |
| 格式 | `member1-numeric-v1`（纯数值 JSON，无 pickle/joblib） |
| 算法 | logistic（6 维，signed-log1p + 标准化 + 线性） |
| SHA-256 | `a91e166cee8b94d3c49b53322782147a696161d9d8eb8e597d5b97ff8065d1bb` |
| 平均 F1 / 最差折 | 0.9919 / 0.9596 |
| 基线（恒预测攻击） | 0.6411 |
| 部署阈值 | 由各折阈值众数确定（非最优折） |
| `validation_gate_passed` | **true**（由真实指标算出，不是手填） |

门槛判据（写进模型的 `gate_basis`）：
> 会话分组交叉验证平均 F1 0.9919 / 最差折 0.9596 vs 恒预测攻击基线 0.6411
> （要求平均超过基线 0.05 且最差折仍高于基线）

### 4.1 数值一致性

部署侧（纯数值推理器）与训练侧（sklearn）在同一批窗口上逐点比对：

```
checked_windows = 500, max_abs_diff = 2.55e-10 (tolerance 1e-9)  -> PASS
```

导出脚本在该校验失败时**拒绝导出**（退出码 2），避免"训练与部署不一致"。

## 6. 不确定性（必须随结果一起报告）

1. `windows_0.jsonl` 由**仓库外脚本**从 ROSPaCe PCAP 派生，生成脚本不在库内；
   本次独立审计了其标签分布与特征定义，但**无法复核其窗口划分算法**。
2. 会话分组只能保证不跨采集段泄漏，**不能证明段内时间自相关已被消除**。
3. 数据集只有 3 个标签（正常 + 2 类 ROS 2 攻击），
   因此结论仅对这两类攻击成立，**不得推广到未知攻击**。
4. 6 维窗口特征与 PCAP 侧统计语义等价，但采样位置不同（订阅侧 vs 抓包侧），
   **数值不保证逐点相同**。
