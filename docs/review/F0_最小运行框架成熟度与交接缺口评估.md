## 2. 当前系统架构

系统为四个 ROS 2 包组成的单机可复现框架：

```text
rg_interfaces   接口定义（Action；本轮新增 Service）
rg_policy       纯 Python 策略与状态模型（可脱离 ROS 独立单测）
rg_gateway      执行边界：准入判定、审计、任务状态机
rg_demo_nodes   演示节点：任务发起方、下游执行模拟、启动配置
```

运行主链：

```text
任务发起方 --Action--> 执行边界网关 --Action--> 下游执行模拟
                          |
                          +-- 审计记录（追加型 JSONL）
                          +-- 任务状态与策略快照（原子持久化）
```

分层边界：通信身份层由安全通信配置承担，任务授权层由网关的权威策略承担；
两层的判定结果与拒绝归因均写入结构化证据。

## 4. M1/M2/M3 成果与限制

| 阶段 | 成果 | 限制（必须在交接时说明） |
| --- | --- | --- |
| M1 | 审计失败不放过、构建不打断运行实例、超时语义明确 | 故障注入参数位于产品代码中，待评审 |
| M2 | 强制模式下的身份认证与资源隔离，越权访问被安全层拒绝 | 结论仅覆盖单机单容器与单一中间件实现；跨主机等价性未验证 |
| M3 | 同一合法主体在不同可信任务阶段获得不同授权结果 | 未确认执行状态不跨重启保留；性能对照实验未开展 |

**共性限制（不因阶段推进而消失）**：

1. 持有管理员凭证的本地进程即可行使管理员权限；单容器内共享用户时，**不构成对本地特权进程的强隔离**。
2. 策略内容摘要只能检测意外变化或证明内容关联，**不等同于数字签名**，不能抵御有写入权限的主体。
3. 状态文件与审计记录之间**没有跨文件原子性**，提交顺序为"先状态、后审计"。
4. 性能类指标（延迟分位、切换耗时）**尚未采集**。

## 7. 尚缺失的模块接入能力

这是 F0 与"能跑通"之间的实质差距。当前仓库**没有任何机制**让其他三名成员把模块挂进主链：

1. **无接口定义**：没有共享数据结构，三人无法约定交换内容。
2. **无模拟件**：无法在模块缺失时跑通端到端，主链无法在"部分模块就绪"状态下运行。
3. **无替换点**：即使成员写好了模块，也没有约定的挂载位置与加载方式。
4. **无故障隔离约定**：模块异常时的行为未定义，存在"异常结果继续传给执行器"的风险。
5. **无研究素材目录**：正常/异常样本无处归集，人员一无法基于既有流量开展研究。

## 8. 团队协作阻塞点

| 阻塞点 | 影响 |
| --- | --- |
| 无源钥隔离 | 同一容器内共享用户，成员之间可读彼此私钥，无法声明"身份不可冒充" |
| 无通信域隔离 | 多个成员同时实验会互相看到彼此的节点与话题 |
| 无共享接口 | 三人无法并行开发，只能各自为战 |
| 无 Mock | 任一模块未完成时无法联调 |
| 无 CI 构建 | 提交破坏构建不会被自动发现 |
| 无分支保护 | 无评审门槛，公开接口可能被单方面修改 |

## 10. F0 对外发布前整改清单（缺口条目）

每条按统一格式给出。

### GAP-01　容器复用时未校验工作区挂载

- **问题描述**：容器创建脚本在容器已存在或已在运行时**直接返回成功**，不校验该容器绑定的宿主工作区是否与当前工作区一致。
- **涉及文件**：`scripts/container_up.sh`（容器复用分支）；对照实现见 `scripts/start_system.sh`。
- **触发条件**：新成员的工作区路径与既有容器绑定路径不同，但容器名相同。
- **对成员开发的影响**：新成员会以为环境已就绪，实际编译/运行的是**别人的工作区**，改动出现在错误目录，且难以察觉。
- **优先级**：P0
- **建议修复方式**：在容器复用分支中读取容器挂载信息，与当前工作区比对；不一致时报错退出并给出明确指引（复用/重建/换容器名）。
- **验收判据**：用不同工作区路径调用容器创建脚本时必须失败并给出可执行指引；路径一致时必须成功。
- **对应负责人**：人员四

### GAP-02　人员一至三的公共接口与共享数据结构缺失

- **问题描述**：仓库中没有三人研究模块的接口定义、输入输出结构或共享数据目录。
- **涉及文件**：需新增（建议独立的共享结构位置，避免改动既有包语义）。
- **触发条件**：任何一名成员尝试把模块接入主链时。
- **对成员开发的影响**：无法并行开发与联调；接口只能口头约定，必然返工。
- **优先级**：P0
- **建议修复方式**：由人员四牵头、四人共同确认，先冻结数据结构与必填字段，再实现示例。
- **验收判据**：三个接口均有字段定义、缺省与错误行为、示例数据与校验方式；且接口变更需四人确认。
- **对应负责人**：人员四（牵头），人员一/二/三（共同确认）

### GAP-03　缺面向新成员的环境搭建指南

- **问题描述**：现有项目说明包含命令清单，但没有"从零开始到跑通"的独立步骤与前置条件清单。
- **涉及文件**：`README.md`（或新增独立指南）。
- **触发条件**：新成员首次搭建环境。
- **对成员开发的影响**：搭建依赖口口相传，交接成本高且不可复现。
- **优先级**：P0
- **建议修复方式**：编写独立指南，覆盖前置条件、获取代码、构建、启动、验证、常见失败与定位方法。
- **验收判据**：**另一名成员仅按指南操作即可完成构建与启动**（对应 F0-10）。
- **对应负责人**：人员四

### GAP-04　Mock 全链路与模块替换能力缺失

- **问题描述**：没有可替换的模拟模块，主链无法在部分模块缺失时运行。
- **涉及文件**：需新增。
- **触发条件**：模块未完成或需单独调试某个模块时。
- **对成员开发的影响**：任一模块缺失即无法端到端验证；三人无法独立开展实验。
- **优先级**：P0
- **建议修复方式**：为三个接口各提供模拟实现，并约定统一的替换点与加载方式。
- **验收判据**：三个模块全部替换为模拟件时端到端仍能跑通；逐个换回真实模块时无需改动其他代码。
- **对应负责人**：人员四

### GAP-05　接口就绪探测依赖按域缓存的图服务

- **问题描述**：探测 ROS 图的可发现性依赖运行时图缓存服务，而该服务**按通信域缓存**；跨域实验后不重置会出现"看不到任何接口"的假失败。
- **涉及文件**：`tests/integration/start_system_check.py`（已在测试侧加入按域重置）；产品侧探测逻辑仍依赖该服务。
- **触发条件**：先在一个域运行实验，再到另一个域做就绪探测。
- **对成员开发的影响**：误判为系统故障，浪费时间排查；也可能掩盖真实故障。
- **优先级**：P1
- **建议修复方式**：探测前显式重置图缓存服务到目标域，或改用不依赖缓存服务的探测方式。
- **验收判据**：跨域连续执行探测不再出现假失败；真实故障仍能被检出。
- **对应负责人**：人员四

### GAP-06　运行期通信域不可按开发实例覆盖

- **问题描述**：通信域在容器创建时确定，运行期无法按开发实例指定。
- **涉及文件**：启动脚本与环境封装脚本。
- **触发条件**：两名成员同时在同一容器内做实验。
- **对成员开发的影响**：互相看到对方的节点与话题，实验结论互相污染。
- **优先级**：P1
- **建议修复方式**：允许通过环境变量按实例指定通信域，并在实例记录中留档。
- **验收判据**：两个实例在不同域同时运行时互不可见，且各自日志可区分。
- **对应负责人**：人员四

### GAP-07　成员间凭证与文件权限不可分

- **问题描述**：容器内以统一用户运行，成员可读取彼此的私钥文件；无法声明"身份不可冒充"。
- **涉及文件**：容器配置与安全配置目录。
- **触发条件**：两名及以上成员共用同一容器。
- **对成员开发的影响**：安全结论在协作场景下不成立；审阅者会质疑隔离有效性。
- **优先级**：P1
- **建议修复方式**：短期按成员隔离工作目录与凭证目录权限并明确声明假设；长期考虑每人独立容器。
- **验收判据**：成员 A 无法读取成员 B 的私钥；或在文档中明确声明该限制并给出适用边界。
- **对应负责人**：人员四

### GAP-08　持续集成不做构建与测试

- **问题描述**：现有工作流只做静态校验与仓库卫生检查，不验证工程能否构建。
- **涉及文件**：`.github/workflows/`
- **触发条件**：提交破坏构建或引入语法错误。
- **对成员开发的影响**：破坏性提交不会被自动发现，直到他人拉取后才暴露。
- **优先级**：P1
- **建议修复方式**：增加轻量构建校验作业（不要求运行 ROS 实验，只验证可构建与单元测试通过）。
- **验收判据**：故意提交一处语法错误时 CI 失败；正常提交通过。
- **对应负责人**：人员四

### GAP-09　成员仓库访问权限未经确认

- **问题描述**：无法由当前权限确认其他三名成员是否已获得仓库访问与合作权限。
- **涉及文件**：仓库设置（非代码）。
- **触发条件**：成员首次尝试克隆或推送。
- **对成员开发的影响**：无法提交代码或发起评审。
- **优先级**：P0
- **建议修复方式**：由仓库所有者人工确认并邀请成员；同时定义分支保护与评审要求。
- **验收判据**：三名成员均可独立克隆、推送分支并发起合并请求。
- **对应负责人**：项目负责人（人工确认）

### GAP-10　分支保护与共享接口审批流程缺失

- **问题描述**：没有书面分支规范、必需检查与共享接口变更审批规则。
- **涉及文件**：仓库设置与团队规范文档。
- **触发条件**：多人并行改动公共接口。
- **对成员开发的影响**：接口可能被单方面修改，导致他人代码失效。
- **优先级**：P1
- **建议修复方式**：定义分支命名与合并要求，明确共享接口变更需四人确认。
- **验收判据**：存在书面规范且已在实际合并中生效。
- **对应负责人**：人员四（起草），项目负责人（确认）

### GAP-11　研究素材目录缺失

- **问题描述**：没有归集正常/异常通信样本的目录与口径说明。
- **涉及文件**：需新增。
- **触发条件**：人员一开始通信行为分析研究时。
- **对成员开发的影响**：样本无处存放，来源与标签无法追溯，实验不可复现。
- **优先级**：P1
- **建议修复方式**：建立素材目录，规定来源说明、标签口径、划分方式与样例。
- **验收判据**：至少一组正常与一组异常样本可追溯来源并被测试引用。
- **对应负责人**：人员一（内容），人员四（目录与规范）

### GAP-12　性能类指标未采集

- **问题描述**：延迟分位、切换耗时等性能指标尚未测量。
- **涉及文件**：需新增实验脚本。
- **触发条件**：撰写参赛材料或做对照实验时。
- **对成员开发的影响**：无法给出性能对照结论，材料只能写目标值。
- **优先级**：P2
- **建议修复方式**：固定条件与样本量，采集判定时延与切换耗时并给出分布而非单点值。
- **验收判据**：形成可复现的性能对照记录，含条件、样本量与分布。
- **对应负责人**：人员三（策略判定时延），人员四（框架开销）
