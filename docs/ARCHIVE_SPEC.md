# 归档规范说明（过程记录类文档）

> **定位**：定义本项目**过程记录类文档**的含义、位置与更新时机。
> 每次系统运行前查阅本文件，运行后更新本文件及对应归档材料。
>
> **边界**：本文件不含源码，不含实现细节，不描述技术原理与机制。
> 只回答"有哪些过程记录、各自是什么意思、什么时候更新"。

---

## 1. 过程记录类文档一览

| 编号 | 文档 | 含义 | 更新时机 | 是否纳入版本控制 |
| --- | --- | --- | --- | --- |
| R1 | 本文件（归档规范说明） | 定义过程记录类文档集合及其含义，是记录体系的入口 | 每次运行后 | 是 |
| R2 | 变更记录 | 逐次记录：改了哪些文件、解决了什么问题、暴露了什么问题 | 每次运行后 | 是 |
| R3 | 验收记录 | 逐阶段记录验收项目、判据、结果与证据位置 | 每次验收后 | 是 |
| R4 | 项目说明 | 项目目标、结构、使用方式与已知边界的对外入口 | 能力或边界变化时 | 是 |
| R5 | 环境核查记录 | 一次性的环境实测留档，用于界定可复现范围 | 环境变化时 | 是 |
| R6 | 依赖说明 | 运行所需依赖与版本约束 | 依赖变化时 | 是 |
| R7 | 证据体系说明 | 说明结构化证据的用途、组成与验收规则 | 证据契约变化时 | 是 |
| R8 | 证据数据契约 | 结构化证据的字段约定，供机器校验 | 契约升级时 | 是 |
| R9 | 安全能力与边界记录 | 声明安全能力范围、前提假设与未覆盖项 | 安全能力或边界变化时 | 是 |
| R10 | 授权策略说明 | 说明授权策略的组织方式与维护要求 | 策略变化时 | 是 |
| R11 | 外部审阅交接材料 | 供外部审阅者独立复核的材料集合与说明 | 需要外部审阅时 | 是 |
| R12 | 需求原文抽取 | 原始需求文档的可检索文本，供逐条对照 | 需求文档更新时 | 是 |
| R13 | 阶段冻结标记 | 以版本标签形式固定"某一阶段的最终状态" | 阶段完成且全部通过后 | 是（标签） |

> R13 说明：阶段冻结标记一经建立即**不得移动或覆盖**，它是历史结论的锚点。

## 2. 每次运行产生的归档材料

| 编号 | 材料 | 含义 | 去向 | 是否纳入版本控制 |
| --- | --- | --- | --- | --- |
| M1 | 原始运行日志 | 运行期直接产生的文本日志 | 本地日志目录 | 否 |
| M2 | 原始结构化测试结果 | 逐场景的机器可读运行结果 | 本地证据目录 | 否 |
| M3 | 本地完整证据包 | 由原始结果汇总、可独立校验的证据集合 | 本地证据包目录 | 否 |
| M4 | 公开脱敏证据 | 经脱敏与安全校验后对外公开的证据副本 | 专用证据分支 | 是（证据分支） |
| M5 | 运行记录条目 | 本次运行在 R2 / R3 中新增的条目 | 见第 1 节 | 是 |

> M1–M3 属**受控本地材料**，是 M4 的来源与比对基准。
> M4 一旦发布即**不得覆盖**；需要更正时应新增记录并说明原因。

---

## 3. 运行后更新流程

| 步骤 | 动作 | 完成判据 |
| --- | --- | --- |
| 1 | 汇总本次运行的原始材料（M1、M2） | 材料齐全，可追溯到具体场景 |
| 2 | 生成本地完整证据包（M3） | 通过完整性校验 |
| 3 | 核对结果用语是否符合第 5 节词表 | 无模糊表述 |
| 4 | 更新变更记录（R2） | 含变更文件、解决的问题、暴露的问题 |
| 5 | 更新验收记录（R3） | 逐项给出结果与证据位置 |
| 6 | 如有能力或边界变化，更新 R4 / R9 / R10 | 与实际状态一致 |
| 7 | 发布公开脱敏证据（M4） | 发布成功并留存发布状态 |
| 8 | **更新本文件**：补充本次新增的记录类型或材料类型；在修订记录中追加一行 | 本文件与本次运行一致 |
| 9 | 复核历史结论未被改写 | 历史条目与标签保持原样 |

> 步骤 8 是本文件的存在意义：**每次运行后本文件都会被更新**，
> 使记录体系本身也处于可追溯状态。

## 4. 记录纪律

| 编号 | 纪律 | 说明 |
| --- | --- | --- |
| P1 | 不删除失败记录 | 失败轮次的日志必须保留，可在证据包中说明排除理由，但不得从磁盘移除 |
| P2 | 不改写历史结论 | 已归档的结论、已建立的标签保持原样；更正以新增条目方式进行 |
| P3 | 不用模糊表述 | 结果只能取第 5 节词表取值 |
| P4 | 不以"已实现"代替"已实测" | 未执行的一律记为未执行 |
| P5 | 不上传密钥材料 | 一切私钥与凭证类材料不得入库、不得进入公开材料 |
| P6 | 不覆盖已发布材料 | 公开材料只增不改 |
| P7 | 记录与材料必须可对应 | 每条结论都能指向具体材料，不得出现无出处的结论 |

---

## 5. 结果用语词表

| 取值 | 含义 |
| --- | --- |
| PASS | 已实测通过 |
| FAIL | 已实测失败 |
| PARTIAL | 部分达成 |
| BLOCKED | 因外部条件无法进行 |
| NOT_RUN | 未执行 |

## 7. 未纳入本规范的内容

以下内容**刻意不写入本文件**，以保持本文件只描述"过程记录"：

- 源码、脚本、命令与配置片段
- 技术原理、机制说明、算法与设计取舍
- 安全机制的内部构成与判定规则
- 具体字段的计算方式与取值范围
- 性能数据与测试细节

上述内容分别由代码本身、R4、R9、R10 及技术类文档承载。
