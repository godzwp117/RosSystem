## 5. 核查发现：既有工具未覆盖重复 JSON 键

### 现象

```text
json.loads('{"a":1,"a":2}')  ->  {'a': 2}      # 静默取最后一个值
```

Python 标准 JSON 解析器**默认接受重复键**并静默保留最后一个值。

### 为什么这是问题

1. 重复键是**协议歧义**：同一份报文存在两种合理解读，接收方与发送方可能不一致；
2. JSON Schema **无法发现**这一点 —— 到达校验器时重复键已经消失；
3. 一个先写合法值、后写恶意值的报文，人工阅读时看到的是合法值，解析器取到的却可能是另一个；
4. 因此它不能靠"Schema 校验通过"来兜底。

### 处置（D1 已实施）

在**共享**校验工具中新增解析阶段的重复键拒绝，并由适配层复用：

```python
def reject_duplicate_keys(pairs): ...      # object_pairs_hook
def load_json_strict_text(text, source):   # 拒绝重复键 + 非有限数值
```

**这是严格新增，不削弱阶段 C 的任何既有规则**：D1 完成后
`validate_team_contracts.py --all` 仍为退出码 0，53 项契约测试仍全部通过
（见 D1 验收报告 §6 回归结果）。
