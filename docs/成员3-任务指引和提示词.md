## 1. 项目背景与竞赛要求

**赛事**：「华为杯」第五届中国研究生网络安全创新大赛 · 创意作品赛
**作品提交截止**：**2026 年 10 月 22 日**

**项目定位**：面向具身智能机器人的 ROS 2 通信可信分析与动态最小权限防护系统。

**安全定位**：系统安全为基础，应用安全为核心，通信证据、身份权限和任务上下文相结合，
**SecurityGateway 负责最终权威准入**。

**你的位置**：你负责**应用安全层**。这是本项目最有区分度的一层 ——
**即使通信身份完全合法，候选动作仍可能违反任务约束**。
你要做的就是识别这种"合法身份 + 违规动作"。

**你的模块只产出建议，不是执行许可。**

**主责**：任务风险分析、违规行为识别和安全建议。

| 违规 | 原因码 |

| 超过频率限制 | `RATE_LIMIT` |
| 策略缺失 | `POLICY_MISSING` |

## 7. 模块输入与输出契约

**输入**：stdin 一个 `ModuleInputEnvelope`（JSON）
**输出**：stdout 一个 `TaskRiskDecision`（JSON）
**诊断日志**：**stderr**（stdout 只能有一个 JSON 对象）

**必须支持四种情况**：

| 状态 | 含义 | 是否推进 |
| --- | --- | --- |
| 任务合法 | 建议放行 | 允许推进 |
| 越权 | 建议阻断 | **阻断** |
| `UNKNOWN` | 无法判定 | **阻断**（不等于允许） |
| `ERROR` | 模块自身失败 | **阻断** |

**重要约束**：

- `producer.source` 只能是 `MOCK` / `EXTERNAL` / `UNKNOWN`。
- `evidence_refs[].kind` 只能是 `MOCK` / `RUNTIME_LOG` / `PERMISSION_FILE_ANALYSIS` /
  `CONTROLLED_SECURITY_EXPERIMENT` / `UNIT_TEST` / `UNKNOWN`。
- **不要修改 Schema 来迁就你的输出。**

## 8. 实现任务与里程碑

| 阶段 | 任务 | 交付 |
| --- | --- | --- |
| M1 | 读懂 `task_policy.yaml` 与策略评估逻辑，复现八种违规原因码 | 复现报告 |
| M2 | 建立**任务风险模型**：从 Action 输入提取风险因子 | 模型 + 特征定义 |
| M3 | **策略关联**：把风险因子与权威策略条款对应起来 | 关联表 |
| M4 | 构造**合法与违规受控场景**（覆盖 ≥4 种违规类型） | 场景集 + 标签 |
| M5 | **一致性/不一致性实验**：你的建议 vs Gateway 权威判定 | 对照结果 |
| M6 | 交付模块 + 独立测试 + `team_demo.py` 联调 | 模块 + 证据 |

**M5 是你的特色**：主动找出"你的建议与 Gateway 判定不一致"的案例并分析原因。
**不一致不是失败，而是有价值的发现** —— 它说明权威策略比研究模块更严格（或相反）。

**关于 M3 动态状态机**：M3 研究在**独立分支**（`feature/m3-dynamic-policy`），
**不是 baseline 的默认能力**。你可以参考其已实现的研究资产，
但**不得未经集成就直接认定为 baseline 功能**，也不得让它成为默认依赖。

## 9. 实验与评价指标

- **违规识别准确率**：按违规类型分别报告
- **误报率**：合法任务被错误判定为违规的比例
- **漏报率**：违规任务被错误放行的比例
- **与 Gateway 的一致性**：你的建议与权威判定的一致/不一致比例
- **失败关闭率**：策略缺失 / 输入畸形 / 无法判定时的阻断比例
- **四状态覆盖**：合法 / 越权 / `UNKNOWN` / `ERROR` 各有测试

**报告要求**：每个违规场景都要有 **Gateway DecisionEvent + NavigationSim Goal**
两侧证据，不能只看你自己的模块输出。

## 11. 必须完成的测试

**单元测试**

- 每种违规类型都有用例（至少 4 种），且原因码正确
- 策略缺失 / 畸形 → 必须失败关闭，**不得默认放行**
- `UNKNOWN` / `ERROR` → 必须阻断
- 合法任务不得被误判为违规

**集成测试**

- 合法任务 → 建议放行 → Gateway `ALLOW` + 下游 Goal **+1**
- 越权任务 → 建议阻断 **或** Gateway `OUT_OF_REGION` + 下游 Goal **+0**
- 三模块全部建议放行但目标越界 → **Gateway 仍阻断**（证明权威性）
- 与 Gateway 的不一致性案例要有记录与解释
