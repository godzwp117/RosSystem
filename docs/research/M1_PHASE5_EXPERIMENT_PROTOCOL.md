# M1 第五轮实验协议（采集前固定）

> run_id：`m1g-20261020T084933Z`
> 版本：v1
> 说明：场景清单、标签条件与验收门槛在**查看最终评估结果之前**写定。
> G2 的机制验证先跑（它回答"能不能看见"），G3 的数据采集按本协议执行；
> 评估阈值在看到 G3 数据之前已经确定在本文件中。

## 1. 场景与标签条件

### 正常（目标 ≥20 个独立会话）

| 场景 | 标签条件 |
| --- | --- |
| `normal-rate` 1/2/5/10/20/50/100/200/500/1000 Hz | 合法发布者，频率在授权工作负载内 |
| `normal-restart` 节点加入后正常退出 | 重启不是违规 |

### 异常（每类目标 ≥5 个独立会话）

| 场景 | 标签条件（定性，非频率） |
| --- | --- |
| `anomaly-flood` 2000 Hz 无界洪泛 | 超出任何授权工作负载 |
| `anomaly-churn` 持续创建/销毁节点 | 异常发现行为 |
| `anomaly-endpoint-recon` 持续新建端点 | 未授权端点操作 |

### 明确排除

* **纯查询侦察**（G2-05）实测在快照上不可见（2 次变化 ≈ 稳定场景），
  因此**不作为可检测攻击类别**参与训练，只作为盲区记录。
  不得为它插入人工特征来凑检出。
* 合法 500–1000 Hz 高负载**必须**标 normal：频率本身不是攻击标签。

## 2. 采集参数

| 项 | 值 |
| --- | --- |
| 窗口 | 30 s，固定、不重叠、左闭右开 |
| 图轮询 | 0.2 s |
| 会话时长 | 40 s（≥1 个完整窗口 + 尾部不完整窗口，后者不计入评估） |
| Domain | 69（独立） |
| 观察资源 | 每会话单话题 + 全图快照 |

会话 = 一次独立采集进程 = 一个独立样本单位。
同一会话的多个窗口**不是**独立样本。

## 3. 数据质量门槛

一个窗口可进入评估必须同时满足：

1. `window_complete = true`；
2. 图通道 `status ∈ {VALID, DEGRADED}`（`FAILED`/`NOT_RUN` 不可用）；
3. 消息通道 `status = OK` **或** 该场景本就无业务消息（graph-only 场景，
   此时允许 `INSUFFICIENT`，因为图特征才是该场景的信号）。

会话级：采集进程非零退出 → 整会话作废。

## 4. 评估设计

* **分组单位**：`session_id`；
* **划分**：留一会话（leave-one-session-out），阈值固定 0.5，不在测试会话上调参；
* **训练集**：其余全部会话；
* **最终盲测**：本轮**不设**最终盲测集 —— 会话数不足以同时支撑调参与盲测。
  这一限制必须在报告中如实写出，不得把评估集同时称作"独立最终测试"。

## 5. 评价指标（预先登记）

必须同时报告，不得只挑最好的：

* 正常会话的 **FPR**（每会话与总体）；
* 每类异常的 **Recall**；
* Precision / F1 / Balanced Accuracy；
* **最差会话**表现；
* UNKNOWN 占比与覆盖率；
* graph-only 场景是否被检出。

## 6. 预登记的验收门槛

| 项 | 门槛 | 依据 |
| --- | --- | --- |
| 正常会话 FPR | ≤ 0.10（每会话） | 通信风险告警的可接受噪声上限 |
| 每类异常 Recall | ≥ 0.80 | 至少 5 个会话中检出 4 个 |
| graph-only 异常 Recall | ≥ 0.80 | G1 修复的直接目的 |
| UNKNOWN 占比 | ≤ 0.20 | 过高则模型实际不可用 |
| 最差会话 F1 | ≥ 0.60 | 防止均值掩盖崩溃 |

**任一门槛不达标 → 判定 `INSUFFICIENT_EVIDENCE`，不导出正式模型。**

## 7. 模型导出门槛（附加）

除上述指标外，还必须同时满足任务书 §23 的全部条件
（数据可信、窗口一致、无泄漏、会话充分、独立测试误报达标、
各异常类别召回达标、UNKNOWN 与覆盖达标、运行时特征可采集、
导出与部署数值一致、SHA 可验证、延迟与开销达标、全仓回归无退化）。

## 8. 失败与重试

* 采集失败（非零退出）→ 记录并**不重试同一 session_id**；
  如需重采必须用新 session_id 并在清单中标注；
* 失败实验保留在清单中，不得删除后只留成功的；
* 若某类异常因环境原因无法构造，如实记为 `NOT_RUN`。

## 9. 调整纪律

如协议需修改：

1. 升版本号（v1 → v2）；
2. 写明修改原因；
3. **不得**在看到评估结果之后回头降低门槛。
