# security/ -- reserved for SROS 2 (DDS-Security) integration. NOT ENABLED.

## Status: placeholder only

方案v1.2 §5.1.1 marks SROS 2 resource isolation as **P1 (extension, not blocking)**,
and the task prompt explicitly forbids claiming authentication or non-bypassable
DDS resource isolation unless Enforce mode has actually been enabled and verified.

Nothing in this directory is active. No keystore, no enclave, no permissions
document, and no key material exist here, and none is generated by the build.
Consequently the current system provides **no cryptographic identity and no DDS
resource isolation**:

* `security_gateway` being the only Action Server on `/rg/guarded_navigate` is a
  *topology* fact, not an enforcement boundary.
* Node names and roles (`operator_node`, `planner_node`, ...) are business
  context. Any process on the same ROS domain can publish or send a Goal to any
  of these resources, including directly to `/rg/nav_execute`.
* The admission control implemented in this deliverable is a *pre-execution
  business-rule gate*: it reliably prevents the Gateway from creating a
  downstream Goal for a rejected request. It does not prevent an unauthorised
  process from talking to the executor.

## What a future P1 phase must add (and must measure before claiming it works)

1. `ros2 security create_keystore` + `create_enclave` for each of the four
   participants, with permissions XML that grants:
   * `planner_node`  -> only `/rg/guarded_navigate` (send goal / get result)
   * `security_gateway` -> `/rg/guarded_navigate` (server) **and** `/rg/nav_execute` (client)
   * `navigation_sim` -> only `/rg/nav_execute` (server)
2. Run with `ROS_SECURITY_ENCLAVE_OVERRIDE` / `ROS_SECURITY_STRATEGY=Enforce`.
3. Evidence required before any isolation claim: an authorised chain that still
   completes, **and** a Planner -> `/rg/nav_execute` direct attempt that fails,
   with the DDS-Security error log retained.

## Key material policy

No key, keystore, certificate or private key may be committed to this repository
(task requirement 10). When P1 is implemented, `security/keystore/` must be
git-ignored and generated per machine.
