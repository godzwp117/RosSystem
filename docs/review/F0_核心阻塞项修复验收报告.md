### A2 T14 真并发隔离

原实现是"先后各跑一次"。现改为：两独立工作区 + 两独立容器 + 不同 Domain（51/52）；
容器名与本轮 `run_id` 关联；**两栈同时 READY** 后各自发送请求；双向交叉检查
（A 的 request_id 不得出现在 B 的日志，反之亦然）；停止 A 前校验容器归属
（容器 ID + **规范化后**的挂载源）；A 停后用**不同** request_id 让 B 完成新 Action；
删除容器前双重校验挂载源属于本轮临时目录。

**实测 28 项断言全部通过**，含两容器内各自完成四包构建、双栈并发就绪、双向无串扰。

## 7. 安全边界

1. **SecurityGateway 是最终应用层执行准入点。** 适配层的
   `READY_FOR_GATEWAY_SUBMISSION` **不是**授权 —— T03 已实证：三个 Mock 全部建议放行、
   适配层判 READY、请求真实到达 Gateway，仍被权威 TaskPolicy 阻断。
2. **DDS-Security 负责通信身份与资源访问控制层**，与业务层准入是两个层面。
3. **Mock 自报身份不构成认证**：`producer` 是自报字段；测试权限矩阵推导不是 DDS 认证。
4. **Docker / ROS Domain 隔离不是强身份隔离**（仅开发环境通信隔离）。
5. **F0 不包含 M3 动态任务状态机**；`task_phase`/`policy_epoch`/`policy_digest` 均为可选字段。
6. **未经验证的安全性质不得宣称已验证** —— 本轮 SROS 2 Enforce 未执行，故不作更强声明。

本轮冻结接口检查：`PatrolNavigate.action`、八个业务原因码、`src/rg_gateway/`、
`security/` 的 Git 差异均为空；未引入 M3 状态机；无 `shell=True`；无按名称批量杀进程。
