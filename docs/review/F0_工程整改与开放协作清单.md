## 0. 分级口径（避免把所有安全研究缺陷都当成 F0 阻塞）

| 级别 | 含义 | 判据 |
| --- | --- | --- |
| **P0** | **阻碍其他成员开始开发** | 不解决，人员一/二/三就无法搭建环境、无法接入、无法提交 |
| **P1** | 影响稳定联调 | 不解决仍能开发，但联调效率低、结论易受污染 |
| **P2** | 非 F0 必需的研究深化 | 属于研究深度或后续扩展，**不阻塞基线发布** |

> 明确否定一种常见误判：**M1/M2/M3 的安全研究缺陷（如性能未采集、跨主机未验证、
> 摘要非签名）不属于 F0 开发阻塞**，它们不阻止其他三名成员开始工作。
> 把它们列为 P0 会错误地推迟整个团队的开工时间。

## P0：阻碍其他成员开始开发

### P0-1　容器复用时不校验工作区挂载（GAP-01）

| 项 | 内容 |
| --- | --- |
| 现象 | 容器已存在/运行中时，容器创建脚本直接返回成功，不检查该容器绑定的是哪个宿主工作区 |
| 影响 | 新成员以为环境就绪，实际在**别人的工作区**里编译运行，改动落到错误目录 |
| 涉及文件 | 容器创建脚本的"复用分支"；可参考启动脚本中已有的挂载比对实现 |
| 修复动作 | 复用分支中读取容器挂载并与当前工作区比对，不一致则报错退出并给出三条指引（改用该工作区 / 另建容器 / 重建容器） |
| 验收 | 用不同工作区路径调用必须失败并给出可执行指引；路径一致时必须成功 |
| 负责人 | 人员四 |

### P0-2　公共接口与共享数据结构缺失（GAP-02）

| 项 | 内容 |
| --- | --- |
| 现象 | 仓库中没有任何面向三名成员研究模块的接口定义或共享数据结构 |
| 影响 | 三人无法并行开发；接口只能口头约定，集成期必然返工 |
| 涉及文件 | 需新增共享结构位置（不改动既有包语义） |
| 修复动作 | 人员四牵头、四人共同确认三个接口的字段、缺省行为、错误行为、可信边界与示例；先冻结再实现 |
| 验收 | 三个接口均有完整定义与示例；变更需四人确认 |
| 负责人 | 人员四（牵头）、人员一/二/三（确认） |

### P0-3　新成员环境搭建指南不足（GAP-03）

| 项 | 内容 |
| --- | --- |
| 现象 | 有命令清单，但没有"从零到跑通"的独立步骤与前置条件 |
| 影响 | 搭建靠口口相传，交接不可复现 |
| 涉及文件 | 项目说明或新增独立指南 |
| 修复动作 | 覆盖前置条件、获取代码、构建、启动、验证、常见失败与定位 |
| 验收 | **另一名成员仅按指南即可完成构建与启动** |
| 负责人 | 人员四 |

### P0-4　Mock 全链路与模块替换能力缺失（GAP-04）

| 项 | 内容 |
| --- | --- |
| 现象 | 无模拟模块、无替换点、无故障隔离约定 |
| 影响 | 任一模块未完成就无法端到端验证；三人无法独立实验 |
| 涉及文件 | 需新增 |
| 修复动作 | 为三个接口各提供模拟实现；约定统一替换点与加载方式；定义模块失败时的行为 |
| 验收 | 三模块全替换为模拟件仍跑通；逐个换回真实模块无需改其他代码；模块异常不污染主链 |
| 负责人 | 人员四 |

### P0-5　仓库成员访问权限未确认（GAP-09）

| 项 | 内容 |
| --- | --- |
| 现象 | 无法由当前权限确认其他三名成员是否已获得仓库访问与合作权限 |
| 影响 | 成员无法克隆或推送，协作无法开始 |
| 涉及文件 | 仓库设置（非代码） |
| 修复动作 | **由仓库所有者人工确认并邀请成员**；随后定义分支保护要求 |
| 验收 | 三名成员均可独立克隆、推送分支、发起合并请求 |
| 负责人 | 项目负责人（人工确认，不可由智能体代办） |

## P1：影响稳定联调

### P1-1　接口就绪探测跨域假失败（GAP-05）

| 项 | 内容 |
| --- | --- |
| 现象 | 探测依赖按通信域缓存的图服务；跨域后不重置会"看不到任何接口" |
| 影响 | 误判为系统故障；也可能掩盖真实故障 |
| 涉及文件 | 启动探测逻辑；测试侧已加入按域重置 |
| 修复动作 | 探测前显式重置到目标域，或改用不依赖缓存服务的探测方式 |
| 验收 | 跨域连续探测不再假失败；真实故障仍被检出 |
| 负责人 | 人员四 |

### P1-2　运行期通信域不可按实例覆盖（GAP-06）

| 项 | 内容 |
| --- | --- |
| 现象 | 通信域在容器创建时固定，运行期无法按开发实例指定 |
| 影响 | 同容器内多人实验互相看到对方节点，结论互相污染 |
| 涉及文件 | 环境封装与启动脚本 |
| 修复动作 | 允许按实例指定通信域，并写入实例记录 |
| 验收 | 两实例在不同域同时运行互不可见，日志可区分 |
| 负责人 | 人员四 |

### P1-3　成员间凭证与文件权限不可分（GAP-07）

| 项 | 内容 |
| --- | --- |
| 现象 | 容器内统一用户运行，成员可读取彼此私钥 |
| 影响 | 协作场景下"身份不可冒充"不成立 |
| 涉及文件 | 容器配置、凭证目录 |
| 修复动作 | 短期按成员隔离目录权限并**在文档中明确声明该安全假设与适用边界**；长期考虑每人独立容器 |
| 验收 | 成员 A 无法读取成员 B 私钥；或该限制已在文档中显式声明并被审阅者看到 |
| 负责人 | 人员四 |

### P1-4　持续集成不做构建与测试（GAP-08）

| 项 | 内容 |
| --- | --- |
| 现象 | 现有工作流只做静态校验与仓库卫生，不验证可构建 |
| 影响 | 破坏构建的提交不会被自动发现 |
| 涉及文件 | 工作流目录 |
| 修复动作 | 增加轻量构建校验（只验证可构建与单元测试，不要求跑 ROS 实验） |
| 验收 | 故意引入语法错误时 CI 失败；正常提交通过 |
| 负责人 | 人员四 |

### P1-5　分支保护与共享接口审批缺失（GAP-10）

| 项 | 内容 |
| --- | --- |
| 现象 | 无书面分支规范、无必需检查、无接口变更审批 |
| 影响 | 公共接口可能被单方面修改，他人代码失效 |
| 涉及文件 | 仓库设置与团队规范 |
| 修复动作 | 定义分支命名与合并要求；共享接口变更需四人确认 |
| 验收 | 书面规范存在且在实际合并中生效 |
| 负责人 | 人员四（起草）、项目负责人（确认） |

### P1-6　研究素材目录缺失（GAP-11）

| 项 | 内容 |
| --- | --- |
| 现象 | 无正常/异常通信样本的归集目录与口径 |
| 影响 | 人员一无法基于既有流量开展研究；样本来源与标签不可追溯 |
| 涉及文件 | 需新增 |
| 修复动作 | 建立素材目录，规定来源说明、标签口径、划分方式与样例 |
| 验收 | 至少一组正常与一组异常样本可追溯并被测试引用 |
| 负责人 | 人员一（内容）、人员四（目录与规范） |

## P2：非 F0 必需的研究深化

> 以下项目**不阻塞团队开工，也不阻塞 F0 基线发布**。
> 列出它们是为了避免被误当成 P0，同时保证不被遗忘。

| 编号 | 事项 | 说明 | 负责人 |
| --- | --- | --- | --- |
| P2-1 | 性能指标采集 | 判定时延与切换耗时的分布，需固定条件与样本量 | 人员三 + 人员四 |
| P2-2 | 跨主机 / 跨中间件等价性验证 | 现有安全结论只覆盖单机单实现 | 人员二 |
| P2-3 | 策略摘要的完整性增强 | 摘要非数字签名，不能抵御有写权限主体 | 人员三 |
| P2-4 | 未确认执行状态的跨重启保留 | 当前未确认计数不跨重启 | 人员三 |
| P2-5 | 密钥轮换与吊销机制 | 当前未启用 | 人员二 |
| P2-6 | 故障注入参数形态评审 | 该参数位于产品代码中，需决定保留或改为测试注入 | 人员四 |
| P2-7 | 安全模式下运维命令行身份 | 当前未给运维命令行分配身份，观测依赖文件证据 | 人员二 |
| P2-8 | 历史归档材料主机标识处理 | 已提交历史中含主机路径，按约束未改写历史 | 人员四 |

## 开放协作的推荐执行顺序

```text
第一步（新成员能进门）
  P0-1 容器挂载校验  →  P0-5 仓库权限确认  →  P0-3 环境指南

第二步（三人能并行开发）
  P0-2 公共接口冻结  →  P0-4 Mock 与替换能力

第三步（联调稳定）
  P1-2 通信域隔离  →  P1-3 凭证隔离  →  P1-1 探测假失败  →  P1-6 素材目录

第四步（工程守护）
  P1-4 CI 构建校验  →  P1-5 分支保护与接口审批

第五步（研究深化，不阻塞发布）
  P2-1 … P2-8
```
